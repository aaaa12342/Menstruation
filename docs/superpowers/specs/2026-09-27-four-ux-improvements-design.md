# 四项本地体验优化设计

## 目标

在不引入 AppID、账号或云服务的前提下，继续提高演示版的内容可发现性、重复使用价值、举报反馈透明度和个人数据控制能力。

## 方案比较与选择

可选方向包括继续扩展模拟后台、集中进行视觉重做、完善用户侧闭环。模拟后台会扩大与正式系统的差距；视觉重做不能解决当前功能缺口。因此选择四项相互独立的用户侧优化：搜索、收藏、举报记录和单帖删除。

## 优化一：科普搜索

- 科普页增加关键词输入框，同时匹配文章标题、摘要、分类以及辟谣标题和解释。
- 分类筛选、关键词和收藏筛选可组合使用。
- 没有匹配项时显示明确空状态，不改变原始内容数组。

## 优化二：本机收藏

- 新建独立收藏服务，以 `type:id` 保存科普或辟谣条目标识。
- 详情页提供收藏/取消收藏按钮；科普页提供“只看收藏”筛选。
- 收藏只保存在当前设备，不保存阅读历史，也不上传。
- 隐私页的删除入口同时清除社区数据与收藏。

## 优化三：我的举报记录

- 新增只读页面，展示当前设备提交的举报原因、时间、内容摘要和处理状态。
- 社区页提供入口；记录不存在时显示空状态。
- 页面不暴露随机设备标识，也不允许修改审核结果。

## 优化四：单独删除自己的帖子

- 只有当前设备创建的帖子显示删除按钮。
- 删除前二次确认；删除后同时清理该帖回复、关联举报和隐藏记录。
- 预置帖子和其他内容不能通过该接口删除。

## 数据与错误处理

- 收藏服务遇到损坏缓存时回退为空集合；写入失败时向页面返回失败结果。
- 社区服务继续兼容旧缓存；举报列表仅返回当前随机设备标识对应的记录。
- 删除接口同时校验帖子存在且作者属于当前设备。
- 内容 ID 无效时保留现有页面，不伪造成功提示。

## 验证

- 新增收藏服务测试和四项优化的服务层测试。
- 扩展页面绑定检查，确保新增页面资源与事件处理函数齐全。
- 复跑社区、举报、回复安全与 JSON 解析检查。

## 边界

所有功能仍是单设备演示。收藏、举报记录和删除不会跨设备同步；正式上线仍需登录/匿名身份策略、服务端授权、审核审计和数据主体请求处理机制。
